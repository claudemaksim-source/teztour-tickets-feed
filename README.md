# Чартерные авиабилеты из Вильнюса — цена «от»

Файл [`tickets-from.json`](tickets-from.json) обновляется раз в сутки и лежит по постоянному адресу:

```
https://raw.githubusercontent.com/claudemaksim-source/teztour-tickets-feed/main/tickets-from.json
```

Адрес не меняется никогда, меняются только цены внутри. `raw.githubusercontent.com` отдаёт файл с заголовком `access-control-allow-origin: *`, поэтому его можно читать прямо из кода на странице Framer. Отдаётся через CDN с задержкой до пяти минут после правки.

## Откуда данные

Открытый чартерный поиск шлюза TEZ: `https://xml.tezapi.eu/ticketsearch/search`. Пароль не нужен, белый список адресов не нужен — этот путь открыт, в отличие от справочников и регулярных рейсов.

Направлений двенадцать, найдены перебором 302 кодов IATA в трёх сезонных окнах. Короткий список однажды уже подвёл: в нём не было Зальцбурга и Мадейры, и оба направления молча выпали.

Горизонт — год. При полугодовом Бургас, Варна, Корфу и Родос выпадали целиком вместе с Болгарией: они начинаются в мае-июне.

## Что внутри

```jsonc
{
  "generated_at": "2026-10-15",
  "source": "https://xml.tezapi.eu/ticketsearch/search",
  "currency": "EUR",
  "origin": "VNO",
  "horizon_days": 365,
  "round_trip_nights": 7,
  "price_basis": "vienam asmeniui",   // цена на одного человека
  "countries": [ /* 7 записей */ ],
  "regions":   [ /* 12 записей */ ]
}
```

Страна и регион устроены одинаково: `slug`, `name`, и две цены — `one_way` и `round_trip`. В каждой цене лежит сумма, даты, номера рейсов и **готовая ссылка на эту самую выдачу** на `teztour.lt`. Цена страны — минимум по её регионам.

Обе цены собираются **отдельными запросами**, и это не прихоть: круговой тариф дешевле суммы двух односторонних — 140+140 за круг против 165+165 по отдельности. Сложением цену туда-обратно получить нельзя.

Записи отсортированы по возрастанию цены, так что первая запись — самое дешёвое направление.

## Ссылка в поле `url`

```
https://www.teztour.lt/flightsearch/<ключ>/from_date/DD.MM.YYYY[/to_date/DD.MM.YYYY]
  /adults/1/route_type/OW|RT/v/2/iataFrom/21129/iataTo/<аэропорт>/charter/1.lt.html
```

- `<ключ>` сайт проверяет только по виду — ровно 32 шестнадцатеричных знака. Здесь он считается хешем от остальных параметров: при неизменной цене ссылка остаётся прежней, иначе в CMS дёргались бы ссылки на каждой сборке.
- `iataTo` — числовой идентификатор **аэропорта**. Буквенный код IATA не принимается, а идентификатор города даёт пустую выдачу: Тенерифе как город (`19704`) не работает, как аэропорт (`38889`) работает.
- Цены на странице совпадают со шлюзом, наценки нет. Проверено на Ираклионе (69 €), Анталии (165 €), Хургаде (450 €), Тенерифе (239 €).

## Как обновляется

Каждую ночь в 03:17 UTC запускается [`build-feed.py`](build-feed.py). Он опрашивает шлюз, пересчитывает минимумы и коммитит файл — только если данные изменились. История коммитов — она же история изменения цен.

### Почему обход бережливый

Полный год по двум типам цен — 8760 запросов в сутки. Единственное ограничение, которое TEZ где-либо документирует, — 50 запросов в минуту (у поиска туров; у поиска билетов не сказано ничего), а без потолка выходило 850—1250. Отказа не было, но полагаться на чужой недосмотр нельзя.

Поэтому найденные цены хранятся в [`prices-cache.json`](prices-cache.json) между запусками, и каждый прогон опрашивает лишь:

- ближние 60 дней, где цены реально движутся;
- даты, на которых сейчас стоит минимум, — чтобы опубликованная цена всегда была свежепроверенной, а не унаследованной;
- одну седьмую дальнего хвоста, так что полный круг выходит за неделю.

Выходит около 2500 запросов вместо 8760, при жёстком потолке 2 запроса в секунду — прогон минут на двадцать. Плата: цена дальнего сезона может быть до недели старее. У Бургаса и Варны минимум всегда в дальней части, поэтому их цифра обновляется раз в неделю.

### Три защиты от неверной цены

Молча опубликованная неверная цена хуже, чем вчерашняя верная.

1. **Повтор запроса.** Сбой шлюза раньше возвращал пустоту, рейс исчезал, и цена подскакивала до следующей по списку. Теперь четыре попытки, и годным считается только ответ с корневым `<Tickets>`.
2. **Порог сбоев.** Не ответило больше 20 запросов — сборка падает, фид остаётся прежним.
3. **Проверка результата.** Регионов не меньше 11, у каждого хотя бы одна цена, ни одна цена не выросла втрое. Нарушение — выход с ошибкой, прежний файл не тронут.

Запас при отказе всё равно сохраняется: это наблюдённые факты, они верны всегда, и следующий запуск не переспрашивает те же две с половиной тысячи дат заново.

Если направление закроют совсем и регионов станет меньше одиннадцати, сборка будет падать каждую ночь, а фид замрёт на последних верных данных. Это сделано нарочно: GitHub пришлёт письмо о падении, и решать должен человек, а не скрипт. После проверки снизьте `MIN_REGIONS`.

## Чего в данных нет

Поле свободных мест шлюз всегда отдаёт равным `10` при любом числе пассажиров — это предел выдачи, а не остаток. В фид оно не попадает: подтвердить наличие по нему нельзя, только запросом на нужное число людей.

Вылет только из Вильнюса. Каунас и Паланга чартеров не имеют вовсе, Рига и Таллин летают, но это другой рынок.
